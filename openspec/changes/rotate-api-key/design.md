# Design: Rotate API Key

In-place secret swap on the SAME `api_keys.id`, so `requests.api_key_id`
attribution, aggregate metrics, and the per-key detail route all survive
rotation. Mirrors the established `updateApiKeyLabel` active-only mutation and
the create one-time-reveal DTO. Implements proposal Approach A and spec
`api-key-management` REQ-1..REQ-8 (14 scenarios).

## Technical Approach

Route generates the new key material (`generateKey()` + `hashKey()`, exactly as
`_handleKeysCreate`); storage performs a single atomic `UPDATE` and never sees
the plaintext. The route holds `full` to reveal once. Status classification
(200/404/409) reuses the rename handler's preliminary-lookup pattern.

## Architecture Decisions

| Decision | Choice | Rationale / Rejected |
|---|---|---|
| Hash swap vs versioning | In-place `UPDATE prefix,key_hash,rotated_at WHERE id=? AND revoked_at IS NULL` | Preserves id/history; rejected dual-hash + version table as out-of-scope for single-operator gateway |
| Where key is minted | Route (`generateKey`/`hashKey`), storage takes `keyHash` | Keeps storage plaintext-free; mirrors `insertApiKey` |
| 404 vs 409 | Preliminary `listApiKeys().find(id)`: absent→404, `revoked_at!=null`→409, active→rotate | UPDATE `changes()` alone can't distinguish; identical to `_handleKeysRename` |
| UNIQUE collision | Do NOT catch — let it throw to server.ts try/catch → 500 | Mirrors `insertApiKey` no-swallow; atomic UPDATE leaves original row unchanged on failure |
| `rotated_at` migration | Add to `CREATE TABLE` + `ensureColumn("api_keys","rotated_at","TEXT")` | Matches existing idempotent additive-column pattern; no framework |
| `is_admin` | Never in SET clause | Preserves privilege; asserted in tests |
| Prefix | Regenerated by `generateKey()` | Locked at spec: new identity surface |

## Data Flow

    POST /api/keys/:id/rotate ─ enforceApiKey (/api/* admin gate)
        │
        └─ _handleKeysRotate (withObservability → attributed audit row)
             ├─ classify via listApiKeys() → 404 | 409
             ├─ generateKey() → {prefix, full}; hashKey(full) → keyHash
             ├─ rotateApiKey(id, prefix, keyHash, rotatedAt)  ── UPDATE api_keys
             └─ 200 literal DTO { …, rotated_at, full }  (full shown once)

## Interfaces / Contracts

```ts
// storage.ts — route computes the hash; storage stays plaintext-free.
export function rotateApiKey(
  id: number, prefix: string, keyHash: string, rotatedAt: string,
): boolean; // UPDATE ... SET prefix=?,key_hash=?,rotated_at=? WHERE id=? AND revoked_at IS NULL

// api.ts (frontend) — full returned exactly once; NO key_hash field.
export interface RotatedApiKey {
  id: number; prefix: string; label: string;
  created_at: string; revoked_at: string | null;
  rotated_at: string; full: string;
}
```

Route returns an EXPLICIT literal DTO (never spread the DB row / `ApiKeyRecord`),
identical discipline to `_handleKeysCreate`/`_handleKeysRename`.

## Resolved Open Questions (from explore #944)

1. Invalidation timing — instant on UPDATE, no grace window (locked).
2. One-time reveal — `RotatedApiKey.full`, never persisted (locked).
3. Admin rotation — `is_admin` excluded from SET; UI can never promote (locked).
4. Revoked key — active-only guard → 409 (locked).
5. Audit trail — `withObservability` writes the attributed request row; no extra table (locked).
6. Self-lockout — `RotateKeyDialog` warns via `isStoredKeyPrefix` (locked).
7. Prefix — regenerated (locked).
8. `rotated_at` — additive nullable TEXT column, shown in detail card (locked).

## Threat Matrix

N/A — no shell, subprocess, git/PR automation, executable-file classification,
or process-integration boundary. The change adds one in-process HTTP route under
the existing `enforceApiKey` `/api/*` admin gate; no matrix row applies.

## Migration / Rollout

Additive nullable `rotated_at` via the existing `ensureColumn` idempotent path —
no data migration, no backfill (NULL = never rotated). Rollback = revert the
branch; leftover nullable column is harmless. Branch `feat/rotate-api-key` off
master, single PR (well under 400 lines).
